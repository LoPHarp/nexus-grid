# Nexus Grid: план проекта

## Одной фразой
Платформа распределённых вычислений: сервер раздаёт задачи подключённым воркерам (десктопным приложениям), собирает результат, переживает падение воркера и показывает всё на живой веб-панели. Есть собственный API.

## Принципы
- Распределение настоящее: воркеры реально считают, панель только показывает.
- ИИ внутри приложения не нужен для сдачи (токены экономим), но есть дорожная карта и одна маленькая настоящая ИИ-фича, если останется бюджет.
- Сначала ядро и демо, потом панель, потом API и ИИ. Если не успеваем, режем с конца, ядро не трогаем.

## Архитектура
- **Сервер** (Python, FastAPI + WebSocket): очередь задач с приоритетами, реестр воркеров, heartbeat, перераспределение задач при падении, хранение истории в SQLite, REST API и поток событий WebSocket, раздача статики панели.
- **Воркер** (Python, пакуется в готовый клиент): подключается по WebSocket, получает задачу, считает, отправляет результат, раз в секунду шлёт heartbeat и метрики («датчики»: CPU, память, температура если доступна). Простое окно статуса (десктоп).
- **Панель** (HTML + JS, canvas, лёгкая графическая библиотека): мозаика, граф воркеров с анимацией, графики метрик, HUD.
- **Протокол**: компактные сообщения; бинарные кадры для результатов плиток (JSON допустим для управляющих сообщений). Схема пакета нарисована в README.

Стек выше предложение. Менять можно только с причиной и пометкой в PLAN.md; приоритет: дёшево по токенам, бесплатно деплоится.

## Типы задач (плагины-обработчики)
1. **Mandelbrot**: разрез на плитки, плитка = задача. Режим «зум»: серия кадров, на выходе видео или GIF.
2. **Image batch**: сжатие, смена размера, конвертация файлов (практическая польза).
Новый тип задачи добавляется одним обработчиком.

## Что должно быть на панели
- Мозаика: плитки закрашиваются цветом воркера, который их посчитал.
- Граф: сервер в центре, воркеры вокруг, импульсы по линиям при передаче задач, упавший воркер краснеет, задачи «летят» к другим.
- Графики по каждому воркеру: нагрузка, температура/память, пропускная способность, глубина очереди, задержка.
- HUD в углу: задач в секунду, задержка, число живых воркеров.
- Кнопка Demo Mode (запуск демонстрации одной командой).

## API
REST + WebSocket, документация OpenAPI (Swagger UI). Ключ доступа в заголовке.
- `POST /api/jobs`, `GET /api/jobs`, `GET /api/jobs/{id}`, `DELETE /api/jobs/{id}`
- `GET /api/workers`
- `GET /api/metrics` (текущие), `GET /api/metrics/history`
- `GET /api/health`
- `WS /ws/events` (поток событий для панели и внешних клиентов)

## Дорожная карта с ИИ (описать в README)
1. Умный планировщик: предсказание длительности задач и выбор воркера.
2. Обнаружение аномалий в метриках (перегрев, скорое падение).
3. Вопросы кластеру обычным языком по метрикам.
Для сдачи: максимум одна маленькая настоящая фича, на бесплатной модели через FreeLLMAPI, с кэшем ответов, чтобы демо не ломалось из-за лимитов.

- **Этап 1. Ядро**: сервер, воркер, очередь, heartbeat, перераспределение, Mandelbrot, тесты, коммит.

## Сценарий демонстрации (для видео)
1. Окно панели в браузере и окно воркера рядом.
2. Запуск четырёх воркеров, нажатие Render, мозаика собирается.
3. Убить один воркер в кадре: сервер замечает пропажу, плитки перераспределяются, картинка дособирается.
4. Показать API: запрос задачи через curl или Swagger.
5. Показать панель метрик и HUD.

## Критерий готовности
Сервер доступен по публичному адресу, панель открывается по ссылке, готовый клиент запускается по инструкции, видео записано, репозиторий и логи токенов в порядке.
